# claude-stack

A from-scratch, lean Claude Code setup for **cloud sessions** (claude.ai/code), also usable locally.

Before: 217 synced plugins, ~201k tokens of always-on context, 99 hooks, 228 MCP servers per session.
After, in a repo using this template: 6 plugins (~2.1k tokens), 3 hooks (a ~40 ms safety guard, a formatter, and a startup dependency install), a 36-line global CLAUDE.md, and permission prompts only for risky commands.

## Set it up (about 10 minutes, once)

1. **Upload the guardrail plugin.** claude.ai → Customize → Plugins → upload `dist/stack-core.zip` (build it with `scripts/build.sh`) → enable it. It syncs into every cloud session, Cowork, and logged-in terminals.
2. **Paste the setup script.** claude.ai/code → environment menu → Edit → **Setup script** → paste [`setup-script.sh`](setup-script.sh). Keep network access at _Trusted_ (default).
3. **Apply the template to each repo** you work on in cloud, then commit:
   ```bash
   python3 /opt/claude-stack/scripts/apply-template.py .    # in a cloud session (if the setup clone succeeded)
   python3 path/to/claude-stack/scripts/apply-template.py /path/to/repo   # anywhere else
   ```
   Fill in the `<placeholders>` in the new `CLAUDE.md`, or ask Claude to fill them from the code.
4. **Pick Auto** in the mode dropdown next to the prompt box, if your plan offers it. The repo allowlist covers the rest.
5. Optional: remove connectors you don't use at claude.ai/customize/connectors.

After enabling new plugins on claude.ai, run `apply-template.py <repo> --refresh-denylist` to keep them out of coding repos. They stay on in Cowork either way.

## What's here

| Path                                               | What                                                                                                                                               |
| -------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `plugin/`                                          | `stack-core` plugin: `guard.py` (deny/ask on destructive, irreversible, or secret-leaking actions) and `format.py` (project formatter after edits) |
| `global/CLAUDE.md`                                 | Working agreement for all projects; embedded into the setup script                                                                                 |
| `scripts/setup-script.tmpl.sh` → `setup-script.sh` | Cloud environment setup script (generated by `scripts/build.sh`)                                                                                   |
| `template/`                                        | Per-repo `.claude/settings.json`, SessionStart install hook, `CLAUDE.md` skeleton                                                                  |
| `scripts/apply-template.py`                        | Merge the template into a repo without clobbering                                                                                                  |
| `curation/`                                        | Plugin keep/off table with measured costs, star/fork curation, monorepo config patterns                                                            |
| `docs/ARCHITECTURE.md`                             | What loads when, what reaches cloud, why each piece sits where it does                                                                             |
| `tests/test_hooks.py`                              | 152 pipe-tests for the hooks: `python3 tests/test_hooks.py`                                                                                        |

## Local use (terminal / desktop)

```bash
claude plugin marketplace add ogmachine/claude-stack
claude plugin install stack-core@claude-stack
cp global/CLAUDE.md ~/.claude/CLAUDE.md
```

Locally you can also turn off all claude.ai plugin syncing with `"syncClaudeAiPlugins": false` in `~/.claude/settings.json`. Cloud sessions don't read that file, which is why the repo-level denylist exists.
